# ReadBoard Go 收口计划：中间层与 macOS 完整功能

更新时间：2026-08-11

## 本轮进度

截至本轮 App 实测：

- 已完成统一远程请求状态、登录/profile API 版本校验，以及 capability + scope 权限模型。
- 已把权限接入共享侧栏、文章列表、阅读器、快捷动作和问题中心的数据请求。
- 已将 `RemoteAccessGateway` 改为宿主机可选能力，Go 不再注入必然失败的假实现。
- Go 设置窗口已形成“本机连接 + 服务端设置”统一侧栏，并复用 Core 设置页面。
- 依赖和导出平台在 Go 中使用服务端语义：展示/填写服务端路径，不调用客户端文件选择器或安装命令。
- B 站与微信登录状态已通过通用授权网关显示，失效后可在 Go 端重新扫码。
- 已消除问题中心与侧栏同时重复拉取源目录造成的启动期超时；单项请求超时显示为部分服务异常，不再误报整台服务器离线。
- 自动测试：Core 217 项零失败；Go 22 项零失败（真实 TLS/Bonjour 两项按环境开关跳过）。
- macOS App 已切换到共享 `ReadBoardDesktopMainFeatureView`；资料库、问题中心、设置导航、服务端依赖和平台登录状态均来自 Core 的共享 Feature。
- 所有读取型远程 gateway 显式传播失败；资料库、源、看板和设置只在请求成功时替换最后有效数据，问题中心无法连接时显示红色服务不可用状态。

本轮三个遗留项已经收口：

- 设置窗口的导航骨架、路由和问题中心模型/列表已进入 Core 的 `ReadBoardFeatures`，Core 与 Go 使用同一实现；空状态只替换列表内容，标题和整体框架不再跳动。
- HTTP 独立往返测试覆盖 profile、资料库、处理、源、授权、导出、配置、管理、维护和依赖任务，并覆盖失效 token、权限不足、协议不兼容、请求解码失败和服务端执行失败。
- 服务端依赖安装/更新已改为白名单异步任务契约，Go 可提交、轮询、显示失败并取消任务；路径和命令始终作用于 ReadBoard 服务端。
- Go 已删除 `ReadBoardCoreSnapshot`、旧共享 UI 产品和无入口的导航兼容层；产品仓库只保留连接、凭据、离线缓存、远程 gateway 装配和平台打包资源。

本计划所列收口项已完成。后续新增功能应直接进入 `ReadBoardContract` / `ReadBoardFeatures`，不再在 Core 与 Go 各自创建同义实现。

## 目标

在继续大规模迁移订阅管理、数据看板和设置 UI 之前，先完成两项基础收口：

1. 服务端与中间层达到可长期稳定服务的状态。
2. Go macOS 正确承载所有已授权的远程功能，不再把客户端本机状态误当作服务端状态。

“完成”不是页面能打开，而是请求失败、无数据、权限不足和服务端不支持能够被准确区分，并且所有可见动作都作用于正确的设备。

## 当前基础

- `ReadBoardServices` 已覆盖资料库、正文、媒体、处理、源管理、源接入、运行状态、导出、管理、配置、平台授权、维护和远程访问。
- 除远程访问服务自身外，Go 已有对应 HTTP 远程网关。
- 服务端已经按设备 token 的 scope 对 HTTP 路由执行授权校验。
- Go 已完成 TLS 证书固定、密码登录、设备 token 保存和服务能力/profile 获取。
- macOS 主窗口直接运行 Core 的共享 `ReadBoardDesktopMainFeatureView`，并注入远程 gateway。

## 收口 1：服务端与中间层

### 1.1 错误不能伪装成空数据

现有部分远程 gateway 使用 `try?` 和默认值兜底。断线、无权限或协议错误可能被 UI 解释成“列表为空”或“运行正常”。

要求：

- 读取型 gateway 的失败状态必须进入统一的远程服务状态。
- 保留业务上的合法空数组；网络失败不能返回同样的空数组而不留痕。
- 问题中心应能区分服务端业务问题和客户端连接问题。
- 写入失败必须向操作发起者提供明确反馈。

### 1.2 API 版本兼容性

- 登录/profile 返回后检查 `apiVersion`。
- 不兼容时停在连接层，不进入主界面。
- 错误信息说明客户端版本和服务端版本。

### 1.3 capability 与 scope 双重门禁

- capability 表示服务端是否实现功能。
- scope 表示当前设备是否获准使用功能。
- macOS 与 iOS 使用同一套权限判断。
- 页面入口、按钮和快捷键均不得只依赖服务端最终返回 403。

### 1.4 服务端专属能力

`RemoteAccessGateway` 管理的是服务端自身监听、证书和设备授权，Go 客户端不应伪装成可调用。

- 将其明确为服务端专属页面/能力。
- Go 不显示远程服务宿主设置。
- 删除会以 `notConnected` 失败的假实现路径。

### 1.5 端到端验证

- 为 profile、资料库、处理、源、授权、导出、配置、管理和维护建立 HTTP 往返测试。
- 覆盖成功、无权限、失效 token、协议不兼容和服务端错误。
- 保留真实 TLS/Bonjour 测试作为可选环境测试，但基础正确性不能依赖它们。

## 收口 2：Go macOS 完整功能

### 2.1 设置分层

Go 设置拆成两个明确区域：

- 本机连接设置：服务器地址、证书、设备权限和断开连接。
- 服务器设置：LLM、处理开关、平台授权、源类型、导出规则、维护与备份。

远程访问服务的监听地址、端口、证书生成和设备撤销保留在 Core 服务端。

### 2.2 修复动作必须可达

- 问题中心的“打开设置”必须进入 Go 的服务器设置目标页。
- 微信/B站授权使用 `AuthenticationGateway` 的通用 challenge/poll/signOut 流程。
- 不依赖 Core 本机 Pro 模块设置 View。

### 2.3 本地路径与服务端路径分离

以下动作不能在 Go 客户端本机执行后冒充服务端结果：

- brew/npm 依赖安装与更新。
- Whisper 模型下载和切换。
- 自定义依赖路径。
- Obsidian 导出目录选择。

要求：

- 依赖命令由服务端执行并返回进度/结果。
- 服务端路径使用文本输入、服务端预设目录或远程目录浏览能力。
- OPML 文件导入导出属于客户端文件，可继续使用本机文件面板。
- 阅读主题、字号和列宽属于客户端偏好，继续保存在 Go 本机。

### 2.4 权限受限界面

- 只读账号只显示阅读功能。
- 没有 `manageSources` 时隐藏源管理。
- 没有 `manageOperations`/`runProcessing` 时隐藏或禁用对应操作。
- 没有授权、导出、配置、维护权限时不显示对应服务器设置页。

## 执行顺序

1. 建立统一远程状态与 API 版本校验。
2. 抽取共享权限判断，接入 macOS 主窗口。
3. 明确服务端专属 `RemoteAccessGateway`，删除 Go 假实现。
4. 建立 Go 服务器设置导航与问题中心路由。
5. 迁移现有可直接远程调用的设置页。
6. 为依赖管理和服务端路径补充缺失契约。
7. 完成 HTTP 往返测试、全权限/只读/断网验证和 App 部署测试。

## 验收标准

- 断网不会显示成“没有问题”或“空列表”。
- API 不兼容时不会进入主界面。
- 只读账号看不到任何写操作。
- 问题中心所有手动修复入口均能到达正确页面。
- Go 上不存在会修改客户端本机依赖、模型或服务端导出路径的误导操作。
- Core 本地访问仍使用本地 gateway，行为不回退。
- 自动测试、HTTP 路由测试和部署后真实界面验证全部通过。
